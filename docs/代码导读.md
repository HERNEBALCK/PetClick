# PetClick 代码导读

这是一个把网页界面放进 Windows 透明窗口的桌面应用。Electron 管窗口和系统能力，HTML／CSS／JavaScript 管画面与动作，小型 C# 程序接收其他软件里的键盘按下和松开事件。

最重要的分工：系统和存档交给主进程，画面和动作交给渲染进程，两者通过 preload 提供的有限接口通信。

## 文件地图

| 文件 | 职责 |
| --- | --- |
| src/main.js | 入口、单实例、透明窗口、托盘菜单、存档和键盘桥接生命周期 |
| src/preload.js | 暴露 window.pet，供界面读取状态、增加次数、订阅事件 |
| src/index.html | 角色、手臂、键盘、计数牌结构，SVG 裁切和遮挡区域 |
| src/style.css | 尺寸、层次、透视、呼吸和口水动画 |
| src/renderer.js | 接收事件、维护按住状态、亮键，调度动作和待机 |
| src/keyboard-layout.js | 104 键位置、物理键映射、左右手分区 |
| src/arm-motion.js | 每只手的状态、目标角度和逐帧补间 |
| src/keyboard-input.js | 启停 C# 子进程，校验消息并转成 KeyA 等编号 |
| src/store.js | 计数、设置、校验、串行写入及备份恢复 |
| src/window-state.js | 固定 160×169 窗口，恢复位置并检查屏幕范围 |
| native/KeyboardBridge.cs | Windows 键盘钩子，只发送物理键标识和按下／松开状态 |

assets 保存原图、透明角色、闭眼帧、局部底图和图标。scripts 和 test 是构建、快捷方式、回归检查。release 是当前便携包和实际运行目录，backups 保存当前版与稳定回退版。node_modules 是开发依赖，保留它可直接继续开发和打包。

## 1. 启动过程

package.json 的 main 指向 src/main.js。主进程固定存档目录为 %APPDATA%\PetClick，申请单实例锁。重复打开只显示原窗口，避免两个程序同时改存档。

随后读取存档，建立透明、无边框的小窗口。原位置已经不在屏幕内时，移回可见范围。窗口加载 index.html，界面通过 window.pet.read() 读取次数并开放点击；联动开启时启动 C# 键盘桥接。

## 2. 按一个 A，为什么她会动

Windows 按下 A → KeyboardBridge.cs 捕获物理按键变化 → keyboard-input.js 校验并转换成 KeyA → main.js 发送 pet:key → preload.js 转交订阅回调 → renderer.js 调用 press('real:KeyA', 'KeyA') → 键帽亮起，选定一只手，开始动作。

C# 用集合记住已经按着的键，过滤长按自动重复事件，并继续把输入交给其他软件。消息通过父子进程的标准输出管道传输，不转换或保存输入文字。

界面里的 pressed Map 记录“此刻有哪些键按着”，不是输入历史。记录包括键名和负责的手；松开时删除记录、熄灭键帽，决定是否回位。键盘事件只走动作路径，不调用增加计数接口。

## 3. 双手和长按

keyboard-layout.js 定义键位和分区。主打字区在 T/Y、G/H、B/N 之间划分；小键盘旋转 180° 面向 Miku，所以实体左半区对应画面右侧手。空格交替分配，方向键和数字区归实体右半区。

左右手各有一份动作状态，能独立动作。同侧多个键按住时，松开最新键后，如果还有其他键按住，就转向剩余键继续保持；只有这一侧全部松开后才回位。

## 4. 原画怎么动，又不出现断手

index.html 用 SVG 遮罩从同一张原画中取出完整的肩部到袖口区域。动作只让整臂绕固定肩膀旋转，不改变长度和粗细。

关键还在于遮挡配合：动作时遮掉身体上的原手臂位置，避免重影；下面显示局部补绘身体底图，填补挪开后露出的部分；移动手臂在键盘前，脸和头发局部又盖住肩部根部。静止或回位后撤掉对应的身体遮罩和补绘底图，恢复原图身体，手臂角度归零。

所有层使用同一坐标系，才能衔接自然。袖套局部缺口复用邻近原画纹理补齐，描边统一收边。pet-backing-v14.png 虽带旧版本号，仍是当前使用的底图，不能当旧文件删掉。

## 5. 定位和动作状态机

renderer.js 的 targetFor() 读取键帽在实际窗口里的中心，换算回原画的 1274×1234 坐标。因此计算考虑了已经旋转、带透视的键盘。

arm-motion.js 的 contactAngle() 比较“肩膀到原袖口”和“肩膀到目标键位”两条方向，求夹角，再限制在合理范围。袖口沿固定半径的圆弧移动，不能像手指一样精确触及每个键，但会随区域改变方向，配合键帽亮起表达联动。

每只手的状态：rest 静止 → lift 抬起 → fall 落下 → hold 按住 → return 回位。

抬起约 90 毫秒，落下约 75 毫秒，回位约 130 毫秒。余弦缓动在当前角度与目标角度间插值，requestAnimationFrame 更新运动画面。长按停在 hold，松开后回位。快速输入从当前角度继续调整，最多保留一次后续敲击，不排成长队，所以停止打字后不会还敲很久。

## 6. 点击计数和持久化

点击键盘／计数牌 → renderer.js 的 countClick() → window.pet.increment() → preload 发送 pet:increment → main.js 调用 Store.increment() → 内存次数加一，返回界面；状态快照排队写入。

主进程是计数的唯一修改者。store.js 把每次快照接到 Promise 链后面依次写入，避免旧次数晚写覆盖新次数。界面比较状态版本号，忽略过期消息。

每次先写临时文件，完成磁盘同步后替换正式文件，再维护有效备份。文件携带 SHA-256 校验值，用于发现损坏，不是加密。启动时主文件损坏就尝试备份；损坏原件保留并提示。保存失败时保留内存次数并后台重试；正常保存没有弹窗。突然断电仍可能丢失未完成写入的末尾点击。

存档在固定用户数据目录，不在 EXE 旁，所以移动或更新程序后仍能读回次数。

## 7. 待机效果

呼吸由 CSS 每 4.5 秒同步上下移动角色相关层，最大约 3.84 像素，键盘和计数牌稳定。输入时暂停在当前呼吸位置，手臂回位后继续，避免跳动。

眨眼每隔随机约 3～7 秒在眼睛区域叠加闭眼素材，其他部分不变；快速输入也可能触发短眨眼。

空闲约 4～8 秒后，从原图分层的口水以嘴边为固定点拉长、变细，再用独立水滴表现断开、下落、淡出。原位置由局部底图清理，结束后恢复原图。输入取消当前滴落和等待计时，空闲后重新安排，避免定时器积累。系统开启减少动态效果时停用呼吸和滴落。

## 阅读顺序

先看 index.html、style.css 认出画面层次，再看 renderer.js 的 press()、release()、countClick()，理解事件如何改变状态。然后读 arm-motion.js 的 press()、sample()，最后追到 preload.js、main.js、store.js。

第一次不用逐个读 SVG 路径坐标和扫描码表，把它们看成“区域形状”和“键位字典”，先理解被谁使用。

## 给别人介绍时可以这样说

“这是一个 Electron 透明悬浮桌宠，用 HTML、CSS 和 SVG 将原画分层，让完整手臂绕肩膀旋转。一个小型 C# 程序接收系统按键的按下和松开，传给 JavaScript，再按左右手分区和键位位置驱动动作状态机、点亮键帽。长按保持姿势，松开才回位。键盘只驱动动作，鼠标点击才计数；主进程将计数串行保存到固定用户目录，提供校验和备份。空闲时用 CSS 和定时器做呼吸、眨眼及局部口水动画。”
